# mqtt-session-broker-go

一个本地可运行的 MQTT 消息代理（Broker），作为设备与网关之间的通信中间层。
零第三方依赖，仅使用 Go 标准库。

## 协议版本与兼容范围

- 实现 **MQTT 3.1.1**（`CONNECT` 协议名 `MQTT`、协议级别 4）；其他协议版本（含 MQTT 5.0）在 `CONNECT` 阶段被拒绝，CONNACK 返回码 `0x01`。
- 支持的报文：`CONNECT/CONNACK`、`PUBLISH`、`PUBACK/PUBREC/PUBREL/PUBCOMP`、`SUBSCRIBE/SUBACK`、`UNSUBSCRIBE/UNSUBACK`、`PINGREQ/PINGRESP`、`DISCONNECT`。
- 支持 QoS 0 / 1 / 2 与**保留消息（RETAIN）完整生命周期**；`$SYS` 之外不实现其他系统主题；通配符开头的过滤器不匹配 `$` 开头的主题（符合协议语义）。
- 不实现认证鉴权；`username/password` 字段会被解析但不校验。
- 不实现 MQTT 5.0 的消息过期间隔、订阅标识符等特性；保留消息在 3.1.1 语义下**永不过期**，仅能被同话题后续保留消息覆盖或清空（没有跨重启持久化，重启即丢失）。

## 会话与消息投递规则

### 主题路由
- 发布主题名不允许包含 `+`/`#` 通配符，违反时连接被断开，原因 `ErrInvalidTopic`。
- 订阅过滤器按协议语义校验（`+` 独占一层、`#` 只能在末尾独占一层），非法过滤器在 `SUBACK` 中以 `0x80` 逐项拒绝，不影响同报文中的其他过滤器。
- 投递 QoS = `min(发布QoS, 订阅授予QoS)`；同一会话的出站消息按入队顺序 FIFO 投递。

### QoS 状态机
- **QoS 1**：出站 `QUEUED → WAIT_PUBACK →(PUBACK) 完成`；重连后在途消息以 `DUP=1` 重发。
- **QoS 2**：出站 `QUEUED → WAIT_PUBREC →(PUBREC) WAIT_PUBCOMP →(PUBCOMP) 完成`；重连后按状态重发 `PUBLISH(DUP=1)` 或 `PUBREL`，不会重复投递应用消息。
- **入站 QoS 2**：收到 `PUBLISH` 先存会话、回 `PUBREC`；同一 `packetID` 的重传只回 `PUBREC` 不重复投递；收到 `PUBREL` 才路由给订阅者并回 `PUBCOMP`。

### 保留消息（RETAIN）
- **写入/覆盖/清除**：收到 `RETAIN=1` 的 `PUBLISH` 后，该消息成为对应话题的最新状态；同话题再来一条保留消息即整体覆盖（载荷与保留时的 QoS 一起更新）；发一条**空载荷**的保留消息表示清除该话题状态。
- **新订阅首投**：订阅成功（`SUBACK` 之后）按话题分别向新订阅者投递当前匹配的、每话题至多一条的最新保留消息，报文中 `RETAIN=1`，让订阅端能区分这是历史状态而非刚发生的实时消息；支持通配符一次匹配多个话题；投递级别 = `min(保留时的发布QoS, 本次授予QoS)`；同一 `SUBSCRIBE` 内多个过滤器命中同一话题只投一条（授予级取命中过滤器的最大值）。重新订阅同一过滤器会再次首投（协议语义的“新订阅动作”）。
- **实时发布不重复**：已在线订阅者收到保留发布时按**普通实时消息**处理，报文 `RETAIN=0`（MQTT-3.3.1-12），不会因为消息被保留而重复投递，也不会把历史保留状态再补推一遍。
- **顺序确定**：代理在订阅对发布者可见**之前**先快照并把匹配保留消息入队，再注册订阅。因此订阅生效后到达的实时消息一定排在该订阅的保留首投之后（同会话 FIFO，互不插队）。
- **QoS2 语义**：`RETAIN=1` 的 QoS2 消息在收到 `PUBREL`（入站 QoS2 完成）时才写入保留状态，与实时路由时机一致。
- **遗嘱**：`Will Retain=1` 的遗嘱在异常断开发布时同样更新保留状态——设备异常掉线后，后来的订阅者首投即可看到其“离线”状态；正常 `DISCONNECT` 不发布遗嘱、也不改保留状态。
- **代理级存储，独立于会话**：保留状态不属于任何会话。会话清理（CleanSession）或过期只删会话自身的订阅与积压，不影响保留状态；保留状态也不会让已清除/过期的会话复活，实时消息不会投给已死会话。保留状态仅存于内存，代理重启后丢失。

### 持久会话与离线消息
- `CleanSession=false`：断线后会话（订阅关系、未完成交接、离线队列）保留；重连时 `CONNACK.SessionPresent=1` 并续传未完成消息。
- `CleanSession=true`：断线即删除会话及其订阅与积压。
- 会话过期（`SessionExpiry>0`）：持久会话断线超过该时长后被清除，离线消息一并丢弃；过期清除后重连视为全新会话（`SessionPresent=0`）。
- 同 `ClientID` 新连接接入时，旧连接被断开（原因 `ErrSessionTaken`），会话状态由新连接继承。
- 遗嘱消息（Will）：异常断开（网络错误、畸形报文、配额断开等）时发布；收到 `DISCONNECT` 的正常断开不发布。

### 资源边界（慢消费者、配额与报文大小）
- **会话级配额** `MaxQueuePerSession`：单会话积压（离线队列 + 在途消息）达到配额后，新投递被拒绝；在线连接以 `ErrQuotaExceeded` 断开，离线会话则丢弃新消息并记录日志。QoS 0 消息对离线会话直接丢弃（协议允许）。新订阅触发的保留消息首投同样计入该配额并共用同一条拒绝路径。
- **连接级写积压**：每连接异步写出队列容量 256 条，写满即判定为慢消费者，以 `ErrSlowConsumer` 断开。
- **单条报文大小上限** `MaxPacketSize`：限制入站报文**剩余长度**（含主题与载荷，不含固定报头），默认 1 MiB。解析器在读完剩余长度字段、**尚未分配报文缓冲**时即做判定：一旦声明长度超过上限，立即关闭该连接，不读取报文体、不触碰任何会话状态（不留半截），原因 `ErrPacketTooLarge`；`CONNECT` 阶段超限同样适用（不创建会话、不回 CONNACK）。该检查在每条连接独立的读协程中进行，不持任何全局锁，不会卡住其他连接。`<=0` 表示仅受协议上限（268435455 字节）约束。边界语义为“**严格大于**上限才拒绝”，等于上限放行。
- 三套机制相互独立、可通过 `errors.Is` 分别判定，可共存于同一代理。

### 可区分的断开/拒绝原因
| 原因 | 含义 |
|---|---|
| `ErrMalformedPacket` | 畸形报文（保留类型、非法标志位、非法 UTF-8、QoS 3、空主题等） |
| `ErrPacketTooLarge` | 单条报文剩余长度超过 `MaxPacketSize`（含 CONNECT 阶段） |
| `ErrInvalidTopic` | 发布主题含通配符或非法 |
| `ErrQuotaExceeded` | 会话积压超配额（含保留首投耗尽配额） |
| `ErrSlowConsumer` | 连接写积压超限 |
| `ErrSessionTaken` | 同 ClientID 被新连接接管 |

所有原因可通过 `errors.Is` 判定；`SUBACK` 的 `0x80` 与 CONNACK 返回码用于客户端侧区分。

## 关键配置项

`broker.Config` / 命令行标志（`cmd/broker`）：

| 配置 | 标志 | 默认 | 说明 |
|---|---|---|---|
| `MaxQueuePerSession` | `-max-queue` | 1000 | 每会话积压配额（条），`<=0` 不限 |
| `SessionExpiry` | `-session-expiry` | 3600 | 持久会话过期秒数，`<=0` 不过期 |
| `MaxPacketSize` | `-max-packet-size` | 1048576 (1 MiB) | 单条入站报文剩余长度字节上限，`<=0` 仅受协议上限约束 |
| 监听地址 | `-addr` | `127.0.0.1:1883` | TCP 监听地址 |

## 本地验证方法

```bash
# 运行全部测试（含竞态检测）
go test ./... -race -v

# 启动代理（显式指定报文大小上限）
go run ./cmd/broker -addr 127.0.0.1:1883 -max-queue 1000 -session-expiry 3600 -max-packet-size 1048576
```

测试覆盖：
- `packet/`：各类报文编解码往返；18 种畸形报文的拒绝原因（日志打印报文类型与判定依据）；有界读取（超限在缓冲前拒绝、边界等于上限放行、`errors.Is(err, ErrPacketTooLarge)` 判定）。
- `topic/`：主题名/过滤器校验与通配符匹配（含 `$` 系统主题规则）。
- `broker/`：并发发布订阅（不丢不重）、QoS2 握手与重传去重、断线重连续传、QoS2 在途恢复、配额耗尽断开、慢消费者断开、遗嘱消息（正常/异常断开）、会话过期与清理（日志打印报文类型、会话状态与判定依据）。
- `broker/` 保留消息新增：保留写入/覆盖/清除、新订阅（含通配符与多过滤器）首投与级别降级、SUBACK 先于首投、在线订阅者不重复/不补推（实时 `RETAIN=0`）、首投与实时消息顺序、保留遗嘱更新、保留状态独立于会话清理与过期、保留首投耗尽配额、超限报文（含 CONNECT 阶段）以 `ErrPacketTooLarge` 拒绝且无半截状态/不影响其他连接。
- `server/`：真实 TCP 链路的端到端发布订阅。

## 代码结构

```
packet/   MQTT 3.1.1 报文编解码（畸形报文给出可区分原因；有界读取）
topic/    主题校验与通配符匹配
broker/   会话状态机、订阅路由、保留消息存储、配额/报文上限与慢消费者管理、连接读写循环
server/   TCP 接入层
cmd/broker/ 可执行入口
```
